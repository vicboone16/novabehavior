## Scope\n\nFour new features, all routed off the main app shell. Each is a self-contained page/component so they can land independently.\n\n```text\n/integrity-check        → Data Integrity Console\n/session-summary        → Session Summary (totals per student × behavior)\n/multi-student-capture  → Batch capture page (interval sampling + entry)\n```\n\nThe interval-sampling controls live inside the batch capture page (per-student, per-behavior config row), so they ship together.\n\n---\n\n## 1. Data Integrity Console — `/integrity-check`\n\n**Page:** `src/pages/IntegrityCheck.tsx`\n\nThree collapsible sections, each backed by a single SQL query (no new tables):\n\n- **Unmapped behaviors** — `student_behavior_map` rows where `bank_behavior_id IS NULL` OR `bank_behavior_id` not in `nt_behaviors`.\n- **Orphan session rows** — `behavior_session_data.behavior_id` not in `nt_behaviors` (groups by student + session, shows row count, frequency, duration).\n- **Missing canonical links** — students with `student_behavior_map` entries but no matching `nt_learner_behavior_assignments` for the same canonical UUID.\n\nEach row shows: student name (resolved via `students` table — never raw UUID per Privacy core rule), behavior label, count, last-updated. Refresh button re-runs the queries. Read-only — no destructive actions in this iteration (those go through the existing canonical migration tools).\n\n---\n\n## 2. Session Summary View — `/session-summary`\n\n**Page:** `src/pages/SessionSummary.tsx`\n\nFilter bar: date range (default last 7 days), optional student picker (`SearchablePersonPicker`), optional behavior picker.\n\nAggregation query (SQL, grouped):\n```sql\nSELECT student_id, behavior_id,\n       SUM(frequency) AS total_freq,\n       SUM(duration_seconds) AS total_duration,\n       COUNT(*) AS row_count\nFROM behavior_session_data\nWHERE created_at BETWEEN $1 AND $2\nGROUP BY student_id, behavior_id\n```\n\nResolves student/behavior names client-side. Renders a sortable table with totals row. CSV export button reuses existing export helper pattern.\n\n---\n\n## 3. Interval Sampling Controls (inside batch page)\n\nPer-student × per-behavior config card with 4 inputs:\n- **Total time (min)** — observation window\n- **Sampling interval (sec)** — partial / whole / momentary cadence\n- **Frequency** — running counter button\n- **Duration** — start/stop timer (seconds)\n\nValidation reuses the rules added earlier (`samplingSec`, `intervalSec`, `totalMin`, `autoStopSec`).\n\nState stored in component memory + persisted as draft via the existing `multi_student_session_drafts` queue (no new schema).\n\n---\n\n## 4. Batch Multi-Student Capture Page — `/multi-student-capture`\n\n**Page:** `src/pages/MultiStudentCapture.tsx`\n\nSingle-screen workflow:\n\n1. **Select students** — multi-select from caseload (chips).\n2. **Select behaviors** — for each student, pick from their `nt_learner_behavior_assignments` (canonical only — surfaces the cleanup work just done).\n3. **Configure intervals** — interval sampling controls (section 3) per student × behavior.\n4. **Capture** — collapsible per-student panels with frequency tap + duration timer; running totals shown live.\n5. **Finalize** — generates one shared `session_id`, writes one `behavior_session_data` row per student × behavior via existing finalize RPC.\n\nReuses `MultiStudentSessionBuilder` plumbing (draft sync, offline queue, generated session ID) — this page is essentially the runtime view of a draft.\n\n---\n\n## Navigation\n\nAdd 3 entries to the main nav (or a new \
